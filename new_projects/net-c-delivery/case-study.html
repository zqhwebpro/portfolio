02 // POINT OF SALE INTEGRATION

Toast POS Online Delivery Architecture

Unlike generic e-commerce plugins (such as default WooCommerce) that require kitchen staff to manually re-type online orders into the cash register, this site bridges directly to Toast POS via the Toast Partner API and webhooks:

End-to-End Toast POS Flow:

  1. Store Selection: The customer chooses their closest local store (e.g., Landisville PA). The frontend fetches that location's Toast GUID (Restaurant ID) and active menu catalog.
  2. Modifier Selection: Customer selects sub size (8" vs 12"), roll preparation (Toasted Amoroso vs Garlic Butter), cheese (Cooper Sharp wiz, Provolone), free veggies, and special instructions.
  3. Toast Order Payload: Order payload is formatted into Toast Orders API v2 JSON structure and transmitted over TLS with store authorization headers.
  4. Kitchen KDS Make-Line: Toast Cloud pushes the order directly to the kitchen's bump-bar KDS screens: cold subs appear at the deli station; cheesesteaks appear at the 450° flat-top; loaded fries route to the fryer monitor.
  5. Direct Courier Telemetry: Upon kitchen bump, Toast Delivery Engine assigns the order to an in-house driver, generating real-time SMS tracking for the customer with live ETA updates.

03 // ECONOMIC IMPACT

Direct Toast Delivery vs. Third-Party Aggregators

Independent pizzerias and sub shops operating on third-party aggregators (DoorDash, UberEats, Grubhub) forfeit up to 30% of every order in commissions, and customers are saddled with inflated sub prices and extra $4-$6 service charges:

Cost Element Parma Direct Toast POS DoorDash / UberEats
12" Philly Cheesesteak $14.95 (Menu Price) $18.50 (24% Markup)
Mega Bacon Cheddar Fries $7.95 (Menu Price) $10.25 (29% Markup)
Delivery & Service Fees $2.49 (Flat direct fee) $7.48 (Delivery + Service fee)
Restaurant Commission Kept 100% Retained Lost 30% to Aggregator
Customer Total Paid $26.85 $38.45 (+43% higher!)
04 // .NET 9 C# CLEAN ARCHITECTURE & EVENT ENGINE

Decoupled .NET 9 C# Solution & Events Web API

To provide high-performance order routing and community event publishing, the backend is architected using .NET 9 C# and modern Clean Architecture principles:

// Solution Structure: ParmaDelivery.sln (.NET 9.0)
├── ParmaDelivery.Core (Entities: CommunityEvent, DeliveryOrder, MenuItem | Interfaces: IEventRepository)
├── ParmaDelivery.Infrastructure (Repositories: JsonEventRepository with SemaphoreSlim thread-safety)
└── ParmaDelivery.WebAPI (Controllers: EventsController | CORS Policy | Minimal Status Endpoints)
  • Community Event Post Engine: Allows restaurant staff to publish custom promotional post cards directly onto the monthly calendar, with customizable headlines, event descriptions, images, custom button labels, hex accent colors, and post hyperlinks.
  • Thread-Safe Concurrency: JsonEventRepository utilizes asynchronous I/O and SemaphoreSlim locks to guarantee thread-safe read/write serialization without external database dependencies.
  • Hybrid Client Architecture: The web client automatically discovers local or remote .NET 9 Web API endpoints (http://localhost:5000/api/events) for live operations, with an instant fallback to localStorage when deployed statically to GitHub Pages.
  • Interactive Blueprint Tooltips: Hovering over architectural components displays live .NET C# source code references, roles, and implementation layers.
