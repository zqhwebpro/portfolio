When you look at modern web interfaces, almost every interaction is reduced to the same mechanical paradigm: mouse clicks, touch taps, or keyboard strokes. But throughout history, divination instruments weren't passive forms—they were tactile, physical, and deliberate. A medieval astronomer turning a brass astrolabe felt the weight of concentric rings aligning with the celestial zenith. A cartomancer drawing tarot cards felt the card stock flex beneath their fingers.

With Zodiac Fortune Board, I wanted to see if I could bring that same ritualistic, physical presence into a standard browser tab. I wanted the webcam to act as a Scrying Mirror—interpreting natural hand kinematics directly on the device without clunky hardware peripherals, external cloud APIs, or laggy UI feedback.

Making touchless computer vision feel satisfying rather than gimmicky is surprisingly difficult. If the tracking jitters by a few pixels, the wheel shakes. If there is even 150 milliseconds of processing delay, the illusion of direct physical control collapses. And if you rely on instant gesture triggers, accidental hand movements ruin the user's focus.

Solving this required engineering across four distinct technical pillars: our architectural build choices, the underlying polar math, the hand tracking classifier pipeline, and procedural audio synthesis.

1. Build Choices: Zero-Cloud Latency & Performance Budgets

Before writing any UI code, I set three strict constraints to make sure the application remained lightweight, responsive, and privacy-respecting:

Core Architectural Decisions

  • Zero Cloud Latency & Complete Edge Privacy

    Video frames from the webcam should never leave the client. No cloud endpoints, no backend computer vision microservices, and no telemetry. Everything runs locally on the browser's WebAssembly and GPU thread via Google's MediaPipe runtime, giving us sub-millisecond local inference.

  • Trigonometric SVG & CSS 3D Over Heavy 3D Engines

    The standard instinct for this kind of project is to reach for Three.js or Babylon.js. But bundling a full WebGL engine adds 800KB–1.5MB of gzipped overhead, increases initial bundle parsing time, and burns battery on laptops. Instead, I rendered the entire astrolabe using pure mathematical SVG polar projections and GPU-accelerated CSS 3D matrix transforms.

  • React 19 & Vite 8 State Machine

    Divination rituals are inherently sequential: Wheel Alignment → Destiny Covenant → Major Arcana Draw → Elder Rune Casting. React 19 handles the higher-level stage transitions cleanly, while Vite ensures sub-200ms production builds with tiny runtime chunks.

By keeping all computation strictly inside the browser sandbox, the application boots instantaneously, requires zero server infrastructure, and works completely offline once cached.

2. The Building Blocks: Sacred Geometry & Polar Horology

The central astrolabe wheel isn't a static image rotated with CSS—it is an interactive trigonometric instrument. The 12 houses of the zodiac are mapped equidistant along a 360-degree circle. To position every node dynamically without hardcoding pixel offsets, the engine converts polar coordinates $(r, \theta)$ into Cartesian space:

Polar Coordinate Projection Trigonometric Placement 
// Equidistant polar placement for 12 celestial houses
const radius = 40; // Percentage offset from center
const angleStep = (2 * Math.PI) / 12; // Exactly 30° (π/6 rad) per house

const signPositions = ZODIAC_SIGNS.map((sign, index) => {
  // Offset by -π/2 so index 0 begins directly at the top Zenith
  const theta = index * angleStep - (Math.PI / 2);
  return {
    ...sign,
    x: 50 + radius * Math.cos(theta),
    y: 50 + radius * Math.sin(theta)
  };
});

Once the nodes exist in vector space, the engine calculates geometric aspect chords between them. In classical horology, angles between signs define harmonic relationships:

  • Trine Chords ($120^\circ$ Separation)

    Signs of the same element (Fire, Earth, Air, Water) sit exactly 4 houses apart. The SVG canvas generates triangular vector chords linking these triads, which brighten and pulse when elemental affinities align.

  • Opposition Vectors ($180^\circ$ Polarity)

    Diametrically opposed signs create structural tension lines across the circle diameter, completing the complex sacred geometry mandala reminiscent of Renaissance astronomical clocks.

  • Zenith Needle & 30° Angular Normalization

    A fixed top pointer determines which house is currently aligned by normalizing the cumulative wheel rotation: normalizedAngle = (-rotation % 360 + 360) % 360. Whenever the wheel crosses a $30^\circ$ house boundary, a synthesized mechanical detent clicks, giving tactile acoustic feedback.

3. Hand Gesture Code Tech: Kinematics & Temporal Hold States

Computer vision in the browser has a reputation for being sluggish and erratic. If a developer naively pipes webcam frames into React component state, the application will drop frames immediately. Hand tremors, low ambient lighting, and finger occlusion cause constant flickering.

To make the interaction feel as rock-solid as a physical trackball, I built a specialized tracking and classification pipeline on top of @mediapipe/tasks-vision:

Decoupled Animation & ML Inference Loops

The human visual system notices dropped frames in UI animations at 60 FPS, but neural landmark detection does not need to execute on every single animation frame. Running full hand landmark inference at 60 FPS creates thermal throttling on most laptops:

  • Throttled Inference Budget (~32ms / 30 FPS)

    The browser’s requestAnimationFrame loop runs at 60 FPS to keep cursor positions and canvas overlays butter-smooth. However, MediaPipe's tensor graph is capped at ~30 FPS using performance.now(). This cuts computational overhead in half without any perceptible loss in tracking responsiveness.

  • Ref-Based Landmark Buffering

    All 21 skeletal hand landmarks are written directly to mutable React refs (rawLandmarksRef.current). React state is only updated when a discrete gesture classification changes or when a deliberate lock triggers, preventing thousands of unnecessary component re-renders.

The 5 Tracked Hand Gestures

Instead of simple finger counters (which easily get confused by curled thumbs or angled knuckles), the classifier uses **normalized Euclidean distance ratios** across four anatomical landmarks per finger: the wrist root, the metacarpophalangeal (MCP) knuckle base, the proximal interphalangeal (PIP) joint, and the fingertip.

☝️ Pointing Vector Continuous Nav

Index extended; middle, ring, pinky curled. Calculates angular coordinates around the wheel center via Math.atan2(dy, dx) to spin the astrolabe with smooth rotational velocity.

✊ Clenched Fist Temporal Lock

All 4 fingers curled down tightly toward the palm. Triggers the 3.0-second continuous hold state machine to lock or unlock the wheel.

✌️ Peace / V-Sign Destiny Panel

Index and middle extended apart; ring and pinky curled. Unveils the Destiny Covenant horoscope summary for the active sign.

✋ Open Palm Tarot Draw

All 4 fingers extended wide. Triggers the Major Arcana tarot card manifestation corresponding to the selected house.

🤘 Mystic Horns Rune Casting

Index and pinky extended; middle and ring curled down. Casts the Three Sacred Elder Runes (Past, Present, and Outcome triad).

useHandTracking.js Normalized Euclidean Knuckle Classifier 
// Geometric knuckle extension check using dual-ratio Euclidean distances
const isFingerExtended = (tip, pip, mcp, wrist) => {
  const tipToWrist = dist(tip, wrist);
  const pipToWrist = dist(pip, wrist);
  const tipToMcp = dist(tip, mcp);
  const pipToMcp = dist(pip, mcp);

  // A finger is only extended if its tip is strictly further than the PIP joint
  return (tipToWrist > pipToWrist * 1.05) && (tipToMcp > pipToMcp * 1.08);
};

// Feature extraction across all four fingers
const isIndexExtended = isFingerExtended(indexTip, indexPIP, indexMCP, wrist);
const isMiddleExtended = isFingerExtended(middleTip, middlePIP, middleMCP, wrist);
const isRingExtended = isFingerExtended(ringTip, ringPIP, ringMCP, wrist);
const isPinkyExtended = isFingerExtended(pinkyTip, pinkyPIP, pinkyMCP, wrist);

// 1. CLENCHED FIST: All 4 digits curled tight
if (!isIndexExtended && !isMiddleExtended && !isRingExtended && !isPinkyExtended) {
  return { gesture: 'FIST', isPinch: false };
}

// 2. POINTING: Index extended, others curled
if (isIndexExtended && !isMiddleExtended && !isRingExtended && !isPinkyExtended) {
  return { gesture: 'POINTING', isPinch: false };
}

The 3-Second Hold Lock Architecture

One of the most persistent failure modes in spatial computing is inadvertent drift. When a user points to align Scorpio at the Zenith and then lowers their hand to read the text, trailing wrist movement will accidentally spin the dial away.

The Deliberate Hold State Machine: To guarantee intent, the interface requires the user to hold a clenched fist (✊ Fist) for 3.0 continuous seconds to lock or unlock the board.

When a fist is detected, a high-precision timer initiates. A radial SVG countdown HUD overlay renders on screen, counting down from 3.0s to 0.0s with an animated golden circular progress ring. If the user breaks the fist pose early (e.g., at 2.1 seconds), the sequence resets cleanly without modifying application state.

Once the 3.0-second threshold completes:

  • Rotational Lockout

    Angular dragging is disabled, ensuring accidental pointer movements cannot disturb the Zenith alignment while reading fortunes.

  • Unmistakable Node Highlighting

    The locked sign node scales up to 1.34x with an illuminated gold border, a dual-layer glowing aura, a pulsing beacon animation, and an illuminated 👑 SELECTED badge.

  • Central Crystal Ball Status

    The center orb illuminates with an imperial status pill: 🔒 [SIGN] LOCKED · Hold ✊ 3s to Unlock.

4. Procedural Audio Tech: 100% Web Audio DSP

Most web experiences load 15MB to 30MB of static MP3 or WAV audio assets. For Zodiac Fortune Board, I took a fundamentally different approach: every frequency in the application is synthesized mathematically in real time using the native Web Audio API.

Zero external audio assets means zero network requests, zero broken CDN links, and instantaneous response times. Even better, procedural audio can be modulated dynamically based on user interaction physics.

The 432Hz Sub-Bass Harmonic Drone

To give the altar an immersive presence the moment it opens, a continuous harmonic drone plays in the background. It uses dual oscillators tuned to ancient Phrygian harmonic intervals (Root A1 at 54Hz and Fifth E2 at 81Hz, aligned with 432Hz tuning) routed through a 140Hz low-pass Biquad filter:

mysticAudio.js Continuous Harmonic Drone Synthesizer 
// Sub-bass harmonic foundation: Root A1 (54Hz) + Fifth E2 (81Hz)
this.droneOsc1 = this.ctx.createOscillator();
this.droneOsc1.type = 'sine';
this.droneOsc1.frequency.setValueAtTime(54, now);

this.droneOsc2 = this.ctx.createOscillator();
this.droneOsc2.type = 'triangle';
this.droneOsc2.frequency.setValueAtTime(81, now);

// Low-pass filter creates warm, subterranean ambient presence
const filter = this.ctx.createBiquadFilter();
filter.type = 'lowpass';
filter.frequency.setValueAtTime(140, now);

this.droneOsc1.connect(filter);
this.droneOsc2.connect(filter);
filter.connect(this.droneGain);

Solfeggio Bell Harmonics via Physical Overtone Ratios

When a destiny covenant or tarot card is revealed, the synthesizer generates crystal bell chimes tuned to sacred Solfeggio frequencies (528Hz, 639Hz, 741Hz, 852Hz, 963Hz).

Real physical bells don't sound like simple sine waves; their acoustic properties produce non-harmonic overtones. To recreate this metallic shimmer, the engine pairs the fundamental frequency with a secondary oscillator tuned to an acoustic bell ratio of **2.76x**, decaying with an exponential volume ramp:

mysticAudio.js Acoustic Bell Harmonic Chime 
// Fundamental chime (e.g., 528Hz Solfeggio frequency)
const osc = this.ctx.createOscillator();
osc.type = 'sine';
osc.frequency.setValueAtTime(freq, now);

// Shimmering overtone at physical acoustic bell ratio 2.76x
const overtone = this.ctx.createOscillator();
overtone.type = 'sine';
overtone.frequency.setValueAtTime(freq * 2.76, now);

// Exponential volume decay over 2.2 seconds
gain.gain.setValueAtTime(0.18, now);
gain.gain.exponentialRampToValueAtTime(0.0001, now + 2.2);

Velocity-Modulated Sweeps & Stochastic Dice Clatter

Other procedural sound design highlights include:

  • Angular Velocity Filter Sweeps

    When spinning the wheel with the pointing gesture, a bandpass filter (Q=3.0, center=350Hz) modulates its frequency dynamically based on the wheel's angular velocity, creating an organic mechanical whoosh that matches physical speed.

  • Stochastic Rune & Dice Bursts

    For elder runes and the 100-sided fate die, a micro-scheduler fires 5 rapid randomized square-wave clicks (between 400Hz and 900Hz) spaced 70ms apart. This clatter resolves into an upward sine sweep (E5 at 659Hz ramping to E6 at 1318Hz), simulating the physical rattle of bone runestones settling onto an altar.

5. Key Engineering Takeaways

Building Zodiac Fortune Board taught me several practical lessons about the intersection of computer vision, interaction design, and browser performance:

  • Temporal Hysteresis is Essential for Spatial Interfaces

    Instantaneous gesture detection sounds good on paper, but in practice it leads to constant false positives and user frustration. Requiring a deliberate 3-second hold turned the fist gesture from an accidental hazard into a satisfying, intentional ritual.

  • Procedural Audio is an Undervalued Superpower

    The Web Audio API can replace megabytes of static sound effects with clean, mathematical synthesis. It eliminates network latency completely and allows audio to respond directly to interactive physics.

  • Edge Machine Learning is Production Ready

    Modern WebAssembly runtimes and WebGL/WebGPU delegates allow complex multi-landmark neural models to run smoothly in standard browser tabs without cloud servers, subscription fees, or user privacy compromises.
