MODULE 01 Zero-DB Session Architecture

PHP Tic-Tac-Toe: Sessions & 2D Matrices

Tic-Tac-Toe provides a foundation in stateful server-side computing without database overhead. It demonstrates array manipulation, turn progression, and victory evaluation algorithms within persistent superglobal state.

Key Architectural Mechanics

2D Session Array

A 3x3 matrix initialized in $_SESSION['board'] preserving cell markers across HTTP requests.

O(1) Victory Matrix

Checks 3 horizontal, 3 vertical, and 2 diagonal lines immediately after every valid turn.

Turn Alternation

Toggles $_SESSION['player'] between 'X' and 'O' upon recording non-colliding cell moves.

Session Reset

Re-seeds the 3x3 empty grid and resets the move counter to cleanly begin a fresh match.

Reference PHP Implementation session_start(); 
// 1. Initialize Board in Session
session_start();
if (!isset($_SESSION['board'])) {
    $_SESSION['board'] = [
        ['', '', ''],
        ['', '', ''],
        ['', '', '']
    ];
    $_SESSION['player'] = 'X';
    $_SESSION['winner'] = null;
}

// 2. Evaluate 8 Winning Conditions
function checkWin(array $b, string $p): bool {
    for ($i = 0; $i < 3; $i++) {
        if ($b[$i][0] === $p && $b[$i][1] === $p && $b[$i][2] === $p) return true;
        if ($b[0][$i] === $p && $b[1][$i] === $p && $b[2][$i] === $p) return true;
    }
    if ($b[0][0] === $p && $b[1][1] === $p && $b[2][2] === $p) return true;
    if ($b[0][2] === $p && $b[1][1] === $p && $b[2][0] === $p) return true;
    return false;
}

MODULE 02 Application Security & Sanitization

Secure Email Contact Form: Input Sanitization & Native mail()

Processing untrusted user input is a core server-side responsibility. This module covers RFC-compliant email validation, XSS prevention via htmlspecialchars(), and defense against CRLF email header injection attacks.

Security & Pipeline Mechanics

filter_var() Validation

Uses FILTER_VALIDATE_EMAIL against RFC 5322 specs to reject malformed sender addresses.

CRLF Injection Defense

Strips carriage returns (\r\n) from the subject line to prevent arbitrary BCC header injection.

htmlspecialchars()

Escapes HTML special entities (ENT_QUOTES, 'UTF-8') to neutralize Stored/Reflected XSS attacks.

MIME Header Assembly

Constructs structured headers (From, Reply-To, Content-Type) for the mail() dispatcher.

Reference PHP Sanitizer filter_var() 
// 1. Sanitize & Validate POST Inputs
$name    = htmlspecialchars(trim($_POST['name'] ?? ''), ENT_QUOTES, 'UTF-8');
$email   = filter_var(trim($_POST['email'] ?? ''), FILTER_VALIDATE_EMAIL);
$subject = preg_replace('/[\r\n]+/', ' ', trim($_POST['subject'] ?? ''));
$message = htmlspecialchars(trim($_POST['message'] ?? ''), ENT_QUOTES, 'UTF-8');

// 2. Defensive Header Construction & Dispatch
if ($email && !empty($name) && !empty($message)) {
    $headers = "From: webmaster@example.com\r\n" .
               "Reply-To: {$email}\r\n" .
               "Content-Type: text/plain; charset=UTF-8";
    mail("contact@example.com", $subject, $message, $headers);
}

MODULE 03 Database & Cryptographic Pipeline

User Authentication: PDO Prepared Statements & Bcrypt

Authentication is the cornerstone of modern web applications. This module implements industry-standard password hashing via password_hash() with blowfish cost factors, timing-attack-safe verification, PDO SQL parameter binding, and session fixation mitigation.

Cryptographic & State Security

Bcrypt Cost Factor

Employs PASSWORD_BCRYPT with algorithmic cost 12 to withstand high-speed offline dictionary attacks.

Timing-Safe Verification

Uses password_verify() to compute constant-time hash comparisons, eliminating side-channel timing leaks.

PDO Prepared Statements

Separates SQL code from user parameters, rendering SQL injection vulnerabilities structurally impossible.

Session Fixation Defense

Calls session_regenerate_id(true) on successful credential validation to invalidate old session tokens.

Reference PHP PDO & Bcrypt password_hash() 
// 1. User Registration with Bcrypt Hash
$hash = password_hash($password, PASSWORD_BCRYPT, ['cost' => 12]);
$stmt = $pdo->prepare("INSERT INTO users (username, email, password_hash) VALUES (?, ?, ?)");
$stmt->execute([$username, $email, $hash]);

// 2. Login Verification & Session Fixation Defense
$stmt = $pdo->prepare("SELECT * FROM users WHERE username = ?");
$stmt->execute([$username]);
$user = $stmt->fetch();

if ($user && password_verify($password, $user['password_hash'])) {
    session_regenerate_id(true); // Neutralize Fixation
    $_SESSION['user_id'] = $user['id'];
    $_SESSION['username'] = $user['username'];
}
