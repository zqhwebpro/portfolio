01 // WHAT IT IS & PURPOSE

Practical Server-Side Engineering & AppSec

Modern web developers frequently rely on heavy, all-inclusive frameworks like Laravel or Symfony that abstract away how the web fundamentally works. However, understanding raw HTTP request-response cycles, server session memory lifecycles, and low-level web application security (AppSec) vulnerabilities is critical for building resilient enterprise systems.

PHP Server Fundamentals is an interactive multi-module server workbench written in clean, modern PHP 8. It demonstrates six indispensable server-side mechanisms: stateful session persistence across stateless HTTP calls, strict mitigation of CRLF email header injection, cryptographic password hashing with session fixation defenses, multi-mime file upload validation, in-memory shopping cart mutators, and secure PDO database interaction.

03 // CODING TECHNIQUES & IMPLEMENTATION

Engineering Mechanics & Security Algorithms

1. Server-Side In-Memory Session State Machine

HTTP is inherently stateless: each request has no knowledge of preceding requests. In Module 1, an interactive Tic-Tac-Toe state machine is maintained across successive HTTP POST submissions using server-side session memory ($_SESSION): 

// Initialize session state if not already set
function initTicTacToe(): void {
    $_SESSION['ttt_board'] = [['', '', ''], ['', '', ''], ['', '', '']];
    $_SESSION['ttt_player'] = 'X';
    $_SESSION['ttt_winner'] = null;
    $_SESSION['ttt_moves'] = 0;
    $_SESSION['ttt_status'] = 'Game in progress. Player X turn.';
}

// Deterministic 8-vector victory evaluation
function checkTicTacToeWin(array $board, string $player): bool {
    for ($i = 0; $i < 3; $i++) {
        // Check rows & columns
        if ($board[$i][0] === $player && $board[$i][1] === $player && $board[$i][2] === $player) return true;
        if ($board[0][$i] === $player && $board[1][$i] === $player && $board[2][$i] === $player) return true;
    }
    // Check diagonals
    if ($board[0][0] === $player && $board[1][1] === $player && $board[2][2] === $player) return true;
    if ($board[0][2] === $player && $board[1][1] === $player && $board[2][0] === $player) return true;
    return false;
}

2. CRLF Email Header Injection Mitigation

When dispatching emails via PHP's native mail() function, attackers frequently inject carriage return (\r) or line feed (\n) characters into the subject or sender fields. This allows an attacker to append arbitrary SMTP headers (e.g. Bcc: victims@spam.com) and transform the server into an open relay.

Module 2 implements defensive regex filtering that inspects headers for newline characters: 

// Detect and reject Carriage Return / Line Feed injection attempts
if (preg_match('/[\r\n]/', $cfEmail) || preg_match('/[\r\n]/', $cfSubject)) {
    $cfErrors[] = 'CRLF Header Injection detected: newlines forbidden in email headers.';
}

// Validate email format according to RFC 5322
$sanitizedEmail = filter_var($cfEmail, FILTER_SANITIZE_EMAIL);
if (!filter_var($sanitizedEmail, FILTER_VALIDATE_EMAIL)) {
    $cfErrors[] = 'Invalid email address format.';
}

// Sanitize output for safe HTML display
$safeName = htmlspecialchars($cfName, ENT_QUOTES, 'UTF-8');
$safeSubject = preg_replace('/[\r\n]+/', ' ', $cfSubject);
$safeMessage = htmlspecialchars($cfMessage, ENT_QUOTES, 'UTF-8');

$headers = "From: webmaster@example.com\r\n" .
           "Reply-To: {$sanitizedEmail}\r\n" .
           "Content-Type: text/plain; charset=UTF-8";

3. Cryptographic Authentication & Session Fixation Defense

Storing passwords as plain text or weak MD5/SHA-1 hashes exposes user databases to instant rainbow-table compromise. In Module 3, passwords are protected using the standard Blowfish crypt algorithm via password_hash(): 

// User Registration: Adaptive Key Derivation (Bcrypt Cost 12)
$hash = password_hash($regPass, PASSWORD_BCRYPT, ['cost' => 12]);

// User Login: Constant-time string comparison against timing attacks
if ($user && password_verify($loginPass, $user['hash'])) {
    // CRITICAL: Prevent Session Fixation attacks by destroying old session ID
    session_regenerate_id(true);

    $_SESSION['authenticated_user'] = [
        'id' => $user['id'],
        'username' => $user['username']
    ];
}

Notice the call to session_regenerate_id(true): this destroys the pre-authentication session identifier and issues a fresh cryptographically random cookie. This defends against session fixation attacks where an adversary primes a victim's browser with a known session ID.

4. Strict Multi-Factor File Upload Validation

File uploads are one of the most hazardous surfaces in server-side development. Module 4 enforces a multi-layer validation pipeline: checking PHP upload error flags, verifying size limits (2MB max), and validating reported MIME types against a strict whitelist before accepting the file: 

$allowedMimes = ['image/jpeg', 'image/png', 'application/pdf', 'text/plain'];

if ($file['error'] !== UPLOAD_ERR_OK) {
    $uploadErrors[] = "Upload failed with error code: " . $file['error'];
} elseif ($file['size'] > 2 * 1024 * 1024) {
    $uploadErrors[] = "File exceeds maximum 2MB size threshold.";
} elseif (!in_array($file['type'], $allowedMimes)) {
    $uploadErrors[] = "Prohibited file type. Allowed formats: JPG, PNG, PDF, TXT.";
}
04 // ARCHITECTURAL TAKEAWAYS

Production Takeaways & Engineering Decisions

  • Defensive Input Hygiene

    Filtering inputs with strict regex checks for CRLF bytes neutralizes SMTP injection attacks at the boundary before mail servers can be coerced into spam relays.

  • Cryptographic Salt Management

    Using password_hash() delegates cryptographically secure salt generation and constant-time string comparison to the PHP C-runtime, preventing timing attacks.

  • Session ID Invalidation on Auth

    Calling session_regenerate_id(true) on every privilege elevation closes session hijacking vectors and maintains robust state isolation.
