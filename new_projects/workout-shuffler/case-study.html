01 // THE PROBLEM & SYSTEM OBJECTIVE

Eliminating Workout Decision Fatigue

Athletes frequently waste 15 to 20 minutes before a session agonizing over workout structure or dealing with congested gym machines. Existing workout applications exacerbate this problem by burying simple routines behind paywalls, cloud accounts, or bloated 8-week structured calendars.

Workout Mixer solves this with an instant, client-side circuit generation engine. The user chooses their available equipment, selects a target split, and receives an ergonomically sequenced workout circuit in under 50 milliseconds. Crucially, the engine enforces physiological balance rules: it prevents consecutive redundant movements (e.g. back-to-back heavy chest presses) and provides tactile visual feedback showing exactly which muscle groups will be stimulated.

03 // CODING TECHNIQUES & IMPLEMENTATION

Engineering Mechanics & Algorithms

1. Anatomical Taxonomy Matching Engine (`MUSCLE_TAG_MAP`)

The underlying open exercise dataset uses inconsistent anatomical nomenclature—some records say "pectoralis major", others say "chest", while leg exercises might specify "quadriceps" or "rectus femoris". A naive string match causes severe bugs: for instance, matching "triceps" will accidentally match "quadriceps" because the substring "riceps" overlaps.

To resolve this, I implemented an anatomical taxonomy dictionary combined with regex boundary detection: 

const MUSCLE_TAG_MAP = {
    chest: ['chest', 'pectorals', 'pectoralis major', 'pectoralis minor'],
    back: ['lats', 'latissimus dorsi', 'middle back', 'lower back', 'traps', 'rhomboids'],
    biceps: ['biceps', 'biceps brachii', 'brachialis'],
    triceps: ['triceps', 'triceps brachii'],
    quads: ['quadriceps', 'quads', 'rectus femoris', 'vastus lateralis'],
    hamstrings: ['hamstrings', 'biceps femoris']
};

// Strict boundary matching avoids substring collisions (e.g., triceps vs quadriceps)
const isExerciseInMuscleGroup = (exercise, groupKey) => {
    if (!exercise || groupKey === 'all') return true;
    const validTags = MUSCLE_TAG_MAP[groupKey];
    if (!validTags) return false;

    const rawTargets = [
        ...(Array.isArray(exercise.primaryMuscles) ? exercise.primaryMuscles : []),
        exercise.target,
        exercise.bodyPart
    ].filter(Boolean).map(s => s.toLowerCase().trim());

    return rawTargets.some(raw => {
        if (groupKey === 'triceps' && raw.includes('quadriceps')) return false;
        return validTags.some(tag => {
            const regex = new RegExp(`(^|\\b|_|\\s)${tag}(\\b|_|\\s|$)`, 'i');
            return regex.test(raw);
        });
    });
};

3. Slot-Level Lock & Pin Randomization Algorithm

Athletes often like four exercises in a generated circuit but want to replace a single exercise (e.g. swapping out pull-ups if all pull-up bars are occupied). The circuit engine implements an immutable slot-anchored pinning state machine. Locked exercises are indexed by slot; running a re-shuffle maps through the slots, preserving locked items in-place while drawing unique candidates for unlocked slots: 

const shuffleCircuit = (currentCircuit, lockedSlots, exercisePool) => {
    const usedIds = new Set(
        currentCircuit.filter((_, idx) => lockedSlots.has(idx)).map(e => e.id)
    );

    return currentCircuit.map((exercise, index) => {
        if (lockedSlots.has(index)) return exercise; // Preserve user-pinned exercise

        // Find available candidate not already present in the active circuit
        const candidates = exercisePool.filter(candidate => !usedIds.has(candidate.id));
        const chosen = candidates[Math.floor(Math.random() * candidates.length)] || exercise;
        usedIds.add(chosen.id);
        return chosen;
    });
};

4. Drift-Proof Monotonic Timing Engine

Standard JavaScript setInterval(fn, 1000) drifts significantly on mobile devices because operating systems throttle background tabs to conserve battery. If an athlete locks their phone between sets, a naive timer can lose 10 to 30 seconds.

Workout Mixer prevents timer drift by anchoring interval calculations to monotonic epoch timestamps: 

// Drift-proof countdown state machine
const startIntervalTimer = (targetDurationSeconds, onTick, onComplete) => {
    const targetEndTime = Date.now() + (targetDurationSeconds * 1000);

    const intervalId = setInterval(() => {
        const remainingMs = targetEndTime - Date.now();
        const remainingSec = Math.max(0, Math.ceil(remainingMs / 1000));

        onTick(remainingSec);

        if (remainingSec <= 0) {
            clearInterval(intervalId);
            onComplete();
        }
    }, 250); // High-frequency polling checks true system time

    return () => clearInterval(intervalId);
};

5. Zero-Asset Procedural Audio Alert

Instead of fetching audio assets over 4G/5G in basement gym settings, countdown warnings are procedurally synthesized using the browser's AudioContext. A short 880Hz high beep signifies countdown warning, while a 1760Hz double-tone signifies transition: 

const playCountdownBeep = (freq = 880, duration = 0.08) => {
    const AudioCtx = window.AudioContext || window.webkitAudioContext;
    const ctx = new AudioCtx();
    const osc = ctx.createOscillator();
    const gain = ctx.createGain();

    osc.type = 'triangle';
    osc.frequency.setValueAtTime(freq, ctx.currentTime);

    gain.gain.setValueAtTime(0.2, ctx.currentTime);
    gain.gain.exponentialRampToValueAtTime(0.001, ctx.currentTime + duration);

    osc.connect(gain);
    gain.connect(ctx.destination);
    osc.start();
    osc.stop(ctx.currentTime + duration);
};
04 // ARCHITECTURAL TAKEAWAYS

Production Takeaways & Engineering Decisions

  • Zero-Telemetry Client-Side Autonomy

    Running the entire dataset and search indexing inside the client eliminates backend infrastructure costs, ensures sub-millisecond response times, and guarantees 100% offline usability inside subterranean gym environments.

  • Touch-Target Ergonomics

    All critical operational controls (shuffle, lock, timer toggle) are sized at minimum 52px touch targets with high-contrast active states, engineered specifically for sweaty hands and vibrating treadmill use.

  • Procedural Synthesis Over Audio Assets

    Synthesizing audio on the fly with native Web Audio eliminates audio decoding latency, network drops, and mobile autoplay restrictions on external media files.
